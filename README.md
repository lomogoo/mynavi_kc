# 🚚 キッチンカー出店調整アプリ

出店日ごとに「出店決定」「声かけ中」のキッチンカーを記録し、日程ごとの目標台数に対する
手配状況をひと目で確認するための Web アプリです。データは Supabase に保存され、
同じ URL を開いている全員に自動で反映されます。

対象日程と目標台数（初期データ・すべて 2026 年）

| 出店日 | 目標台数 |
| --- | --- |
| 9/19（土）・9/27（日）・10/3（土） | 2〜3台 |
| **10/18（日）・10/24（土）** | **4〜5台** |
| 11/7（土）・11/21（土） | 2〜3台 |

目標台数は画面上の「目標 ◯ 〜 ◯ 台」からいつでも変更できます。

---

## セットアップ（初回のみ・約2分）

### 1. Supabase にテーブルを作る

publishable key だけではテーブルを作成できないため、この 1 手順だけ手作業が必要です。

1. [Supabase ダッシュボード](https://supabase.com/dashboard/project/tfkzsbwhvhgxbnnfwtou/sql/new) の **SQL Editor** を開く
2. [`supabase/schema.sql`](supabase/schema.sql) の中身をすべて貼り付ける
3. **Run** を押す

これで `kc_events`（出店日）と `kc_entries`（キッチンカー）が作られ、7 日程の初期データも
入ります。SQL は何度実行しても安全です（既存データは消えません。ただし 10/18・10/24 の
目標台数だけは毎回 4〜5台に揃えられます）。

> アプリを先に開いた場合は、画面に案内と「SQL をコピー」ボタンが出るので、そこからでも同じ作業ができます。

### 2. アプリを開く

ビルド不要の静的サイトです。次のどれでも動きます。

```bash
# ローカルで確認する
npm start          # → http://127.0.0.1:8080
```

- **GitHub Pages**: リポジトリの Settings → Pages → Branch を選んで公開
- **社内サーバー / 共有フォルダ**: `index.html` と `assets/`、`supabase/` を丸ごと置くだけ

`file://` で直接開くこともできますが、セットアップ案内の SQL 表示が動かないため、
簡易サーバー経由（`npm start`）を推奨します。

## 使い方

| やりたいこと | 操作 |
| --- | --- |
| キッチンカーを登録する | 日付カードの「＋ キッチンカーを追加」 |
| 決定 / 打診中 を切り替える | 各行の **決定 / 打診 / 見送** ボタン |
| 連絡先やメモを直す | 各行の「編集」 |
| その日の目標台数を変える | カード下部の「目標 2 〜 3 台」 |
| 会場・搬入時間などを残す | カード下部のメモ欄 |
| 日程を増やす / 減らす | 「＋ 日程を追加」/ カード下部の「日程を削除」 |
| 出店要項を確認する | ヘッダーの「📄 出店要項」（Google スライドが別タブで開きます） |
| 一覧を Excel で見る | ヘッダーの「CSV」 |
| 更新履歴に名前を残す | ヘッダーの「担当者」 |

### 画面の見かた

- カードの右上バッジ … `決定台数 / 目標台数`。目標に達すると緑、未達は赤・黄、超過はオレンジ
- 枠線 … 目標達成で緑、不足でオレンジ
- 上部のサマリー … 決定台数・声かけ中・目標クリア日数・**不足台数**の合計
- 「見送りも表示」のチェックを外すと、断られた先を畳んで現状だけ見られます
- 同じ店名を入力すると、過去に登録したジャンル・連絡先を自動で補完します

### 同期のしかた

ヘッダー右のバッジが同期状態を示します。

| 表示 | 意味 |
| --- | --- |
| 同期中 | Realtime 接続あり。他の人の変更が即時に反映されます |
| 定期更新 | 20 秒ごとに自動再読込（Realtime が使えない環境でも同期されます） |
| 未接続 | Supabase に到達できていません。「再読込」を押してください |

## 構成

```
index.html                 画面（1ページ）
assets/config.js           Supabase の URL / publishable key / 出店要項の URL
assets/app.js              アプリ本体（依存なしの素の JS）
assets/styles.css          スタイル（ライト / ダーク自動切替）
assets/vendor/             supabase-js を同梱（CDN 依存なし）
supabase/schema.sql        テーブル・RLS・Realtime・初期データ
tests/                     Playwright による結合テスト
```

### データモデル

- `kc_events` … 出店日 1 行。`target_min` / `target_max` が目標台数（既定は 2〜3台、10/18・10/24 は 4〜5台）
- `kc_entries` … キッチンカー 1 台。`status` は `confirmed`（出店決定）/ `pending`（声かけ中）/ `declined`（見送り）

## テスト

```bash
npm install
npx playwright install chromium   # 初回のみ
npm test
```

テストはローカルの PostgREST 互換モック（`tests/mock-supabase.mjs`）に対して実行され、
本番の Supabase には一切アクセスしません。

## セキュリティについて

`assets/config.js` の key はブラウザに公開される前提の **publishable（anon）key** ですが、
`supabase/schema.sql` の RLS ポリシーは「誰でも読み書きできる」設定にしています。
**この URL を知っている人は誰でもデータを編集・削除できます。** 社内の関係者だけに
共有してください。

より厳しく制限したい場合は、Supabase Auth でログインを必須にし、`schema.sql` の
ポリシーを `to authenticated` に変更してください。

## 出店要項リンクの差し替え

ヘッダーの「📄 出店要項」の遷移先は `assets/config.js` の `guidelinesUrl` です。
資料を差し替えたときはここだけ書き換えてください（空文字にするとボタンが消えます）。
リンク先の Google スライドは、共有相手にも閲覧権限が必要です。
